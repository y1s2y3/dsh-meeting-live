# 会议纪要（dsh-meeting-live）

> DSH Desktop 插件（**自研版本**）：**把一场会议从「说过就忘」变成「可检索、可交付、可执行」**。
> 录音／录屏边说边出字 → AI 整理成结构化纪要 → 待办一键写进 DSH 待办 → 导出 Word / HTML 发给不在场的人。
> Windows 上录音时还有置顶小浮窗，**页面可以关掉，会照样记**。

- 当前版本：**1.5.1**
- 维护者：**DinosaurYSL**
- 运行环境：DSH Desktop ≥ 2.0.17（Windows 10/11 功能最完整）
- 许可：MIT

## 一、它解决什么问题

开完一场会，通常会发生四件事：没人愿意写纪要、写了也是流水账、行动项散在聊天记录里、腾讯会议的录制文件躺在硬盘里吃灰。

这个插件把这条链路做成自动化：

- ① **会议进行中**：打开录音，边说边出字；需要留证就同步录屏（会后出 MP4 + WAV）。
- ② **会议结束后**：一秒点「AI 生成纪要」，得到一句话结论、决策、风险、待办。
- ③ **待办确认后**：勾选写入 DSH 待办（工作轨），带负责人和截止时间，进度可跟踪。
- ④ **需要交付时**：导出 Word / HTML / Markdown，直接发群或打印。

一句话：**会还是那个会，但会后不用再花半小时整理，也不会漏掉谁答应了什么。**

## 二、核心功能

### 2.1 三个入口，会议都能进来

| 入口 | 适用情况 | 你得到什么 |
| :-- | :-- | :-- |
| ① 实时录音／录屏 | 现场开会、线上会（外放） | 边说边出字；勾「同步录屏」会后得到 MP4 视频 + 独立 WAV 音频 |
| ② 录音转写 | 手上有会议录音／视频文件 | 导入 m4a / mp4 / wav / mp3 / webm，自动转成文字并存成会议 |
| ③ 导入纪要 | 别人已经给了文字（腾讯会议纪要、聊天记录、txt/md/json） | 原文入库，再让 AI 整理成结构化纪要 |

三个入口都在左侧快捷键；会议列表每次录音或导入一条，0 字不留空壳。

### 2.2 边说边出字：本地优先的转写

- **默认本地识别**：Paraformer-zh 中文模型 + pyannote 分段 + cam++ 声纹，**音频不出本机**，离线可用；首次使用需下载模型（合计约 245 MB，可在设置页里下载／重装／卸载）。
- **真说话人分离**：本地引擎默认开启，输出 S1 / S2 与时间轴，多人会议能看出「这句话是谁说的」。
- **实时出字**：约 5 秒一个分片，通常 6–10 秒看到文字；静音、暂停都不会中断整场记录。
- **整段重转写**：实时分片难免有断句和错字；会后点一次「整段重转写」，按 30 秒切片重跑整场，进度可见，结果明显更完整。
- **转写纠错 + 术语表**：录音结束后用总结模型把错别字、人名、专有名词改对（只改写法不改内容），人名与项目名词可加进术语表。
- **从文件夹自动整理术语**：可一次选**多个**放会议纪要／转写稿的文件夹（支持 .txt / .md / .json / .csv / .log / .html / .xml / .docx / **.xlsx** / **.pdf 文本层**），插件通读后抽取专业术语、产品／系统名、机构名、真实人名，**按重要性排序、最多保留 50 个**。解析结果先显示在下方的**候选框**里（带勾选、支持全选/清空），勾选后点「**采纳选中**」加到上方「术语表」输入框（一行一个、顺序即优先级），确认后再点「**保存术语**」写入术语库并用于转写纠错。术语保存在本机设置里。
- **云端转写可选**：科大讯飞、阿里云（一句话识别，按时长计费）；腾讯云接入中。未填凭据时会明确提示缺哪个字段，不会静默失败。

### 2.3 结构化纪要：像腾讯会议 / 通义听悟那样，读完就能掌握全貌

「AI 生成纪要」不是简单几行摘要，而是一份有细节、可交付的结构化纪要：

- ① **一句话结论**（不超过 60 字，写最重要的决定/结论）
- ② **整体概述**（约 400–800 字，自动分 2–4 段：背景/判断 → 讨论与分歧 → 结论与下一步）
- ③ **关键词**（5–15 个项目/系统/指标标签，便于快速扫读与检索）
- ④ **关键要点** 6–10 条（带人名、数字、系统名等具体信息）
- ⑤ **章节速览** 4–12 节：每节标题 + 2–4 句章节摘要 + 3–8 条具体要点（按会议顺序）
- ⑥ **决策事项**（带负责人，并尽量写明「依据/影响」）
- ⑦ **风险／待确认**（带等级，并尽量给出「应对建议」）
- ⑧ **待确认问题**（需要会后核实的事实、数据口径、外部依赖）
- ⑨ **发言人总结**（本地说话人分离能区分 A/B 或 S1/S2 时，按人总结关注点与承诺）
- ⑩ **参会人**（从原文识别，识别不出留空，不编造）
- ⑪ **待办清单**：交付物 + 负责人 + 截止时间 + 优先级 + 验收/依赖说明
- ⑫ **建议标题**（原标题太泛时会自动起一个 8–20 字的标题，可随时改）

详情页的「AI 会议纪要」卡片默认收起，点「展开」可以看完整章节、决策依据、风险建议、待确认问题与发言人总结，也可以一键复制全文。卡片内部按「结论摘要 → 关键词 → 关键要点 → 章节速览 → 决策 / 风险 → 待确认 → 发言人」分区：宽屏下关键要点和发言人是两列、决策与风险并排，窄屏自动堆叠，长纪要读起来不累。老纪要是旧格式也能正常显示；**想看到新的详细版本，需要对那场会议点一次「重新生成纪要」**（历史数据不会自动重写）。

总结默认跟随 **DSH 当前默认模型**，也可以在设置里单独指定一个（含任意 OpenAI 兼容接口 `/chat/completions`），支持「测试连接」。

### 2.4 待办落地：行动项不再停在嘴上

- 勾选待办 → 「写入待办」→ 写进 **DSH 待办的「工作」轨**（和 `dtodo` 同一份存储），带负责人、截止时间、备注；高优先级自动进「重要紧急」象限。
- 不需要的待办可以「弃用」（从列表移除、不写入），底部可「恢复全部弃用」。
- 已写入的条目在待办面板里单独查看、改期、标记完成；重复写入不会重复创建。
- 「重新生成待办」只补抽新的行动项，已写入、已弃用的状态都保留。

> 「写入待办」依赖 `dsh-memory-evolve` 插件；没装时按钮置灰，其他功能不受影响。

### 2.5 导出与分享

一场会议可导出三种格式，文件都带日期与标题：

- ① **Word（.docx）**：深蓝标题、居中元信息、带底纹的结论区、分色章节标题、隔行底纹的待办表格，原文自动另起一页——可直接作为会议纪要归档或打印。
- ② **HTML**：单文件、带样式，双击就能看，适合发群或转 PDF。
- ③ **Markdown**：贴进 wiki / issue / 公众号后台。

### 2.6 桌面浮窗：开会时不占屏

Windows 上开始录音后自动出现置顶小浮窗（小球 + 气泡）：

- 显示录音状态、时长、实时文字；说话音量大时球会有音量光晕（参考腾讯会议）。
- 气泡里可直接**暂停／继续／停止**，也能切换麦克风输入设备（只切换，不打断会议和计时）。
- 球可拖动并记住位置；录音结束自动收起。
- 非 Windows 平台自动退回页面底部录音条，功能不丢。

### 2.7 自动识别：腾讯会议录完自动入库

- **腾讯会议解析**：读取本机腾讯会议录制目录（Windows 默认「文档\TencentMeeting」，可手动选目录），只自动导入 14 天内生成的新录制；mp4/m4a 会先用 ffmpeg 转码再识别。
- **自定义监控目录**：你指定的文件夹出现音频／视频（mp4/m4a/wav/mp3/aac/webm/mov 等）或文本（txt/md/json/docx）就自动导入转写。
- 两个开关独立、**默认关闭**，新装不会被历史文件刷屏；设置页可看「上次扫描 / 已导入 / 失败来源」，也能随时「立即扫描」。

> 注意：腾讯会议云端「智能纪要」没有个人 API，这里抓的是**本机录制文件**。没有本地录制时，可以把导出的纪要文件放进监控目录。

### 2.8 在对话里用：把会议交给 AI

插件自带 8 个面向模型的小工具和 1 个随插件生效的技能（`meeting-minutes-workflow`），所以在 DSH 里直接说人话就行：

- ① 「把这个录音转成纪要」→ 转写并生成结构化纪要
- ② 「上周产品会的待办都有哪些？」→ 搜会议库、列出待办
- ③ 「第 1、3 条待办写入待办」→ 你确认后才写入（**不会自动写**）
- ④ 「把这场会议导出成 Word」→ 生成文档并给出路径
- ⑤ 「腾讯会议自动识别开着吗？」→ 查状态、开关、立即扫描

工具清单：`meeting_list`、`meeting_get`、`meeting_create`、`meeting_transcribe`、`meeting_summarize`、`meeting_push_todos`、`meeting_export`、`meeting_auto_ingest`。

### 2.9 设置与首次引导

设置弹窗三页（统一宽度，切页不跳动）：

- **模型配置**：本地模型下载／重装／卸载、云端转写凭据与校验、总结模型（DSH 默认或手动接口）。设置分四页：**模型配置 / 转写纠错 / 自动识别 / 问题反馈**；「转写纠错」是独立菜单，放自动纠错开关、手填术语表和「从文件夹提取术语」。
- **自动识别**：腾讯会议目录、自定义监控目录、扫描状态与最近导入。
- **问题反馈**：公众号「PM的AI手记」扫码关注与对话指引、常见问题速查（二维码是插件内置图，点图看大图）；
  页面底部有「版本与更新」：显示当前版本，可「检查更新」（只查询并提示新版本与下载页，**不会自动安装**）。

首次使用会弹一次引导：① 下载本地模型或配置云端转写（可直接跳设置）；② 提示安装 `dsh-memory-evolve`（待办写入依赖）。

## 三、为什么值得用（价值）

- **① 省时间**：一小时会议，会后几分钟内拿到结构化纪要，不用再回放录音、不用边听边打字。
- **② 不漏项**：结论、决策、风险、待办是固定结构，不会出现「会开了两小时，纪要只有流水账」；待办连带负责人、截止、优先级一起抽出来。
- **③ 能落地**：行动项一键进 DSH 待办并进入日常工作台，谁答应的事、什么时候交，都有据可查——这是这套工具和「只做转写的录音笔」最大的区别。
- **④ 隐私可控**：默认本地识别，**音频不出本机**；只有你主动切到云端引擎时音频才会上传，且计费、凭据都由你掌握。
- **⑤ 不打断会议**：录音开始后浮窗接管，主界面可以关掉；会议投屏、共享屏幕时不需要切来切去。
- **⑥ 可交付、可检索**：Word / HTML / Markdown 直接交付；历史会议可按标题、参会人、正文搜索，也能让 AI 在对话里读原文核对。
- **⑦ 零操作入库**：腾讯会议录完、或录音文件放进监控目录，自动转写入库，事后只剩「看一眼纪要、确认待办」两件事。

## 四、快速开始

### 4.1 环境前提

| 前提 | 必须？ | 说明 |
| :-- | :-- | :-- |
| DSH Desktop | 必须 | ≥ 2.0.17 |
| Windows 10 / 11 | 推荐 | 桌面浮窗、腾讯会议目录解析、录屏转 MP4 都在 Windows 上最完整 |
| ffmpeg | 录屏、腾讯会议录制（mp4/m4a）自动转写、在对话里转写本地音视频时需要 | 缺 ffmpeg 时：录屏不可用（勾了也只会录音频）、非 WAV 的自动转写/工具转写会失败；实时录音转写、页面导入、纯文本纪要不受影响。自动探测 PATH / winget 目录，也可设 `FFMPEG_PATH` |
| `dsh-memory-evolve` | 可选 | 「写入待办」依赖它；没装则按钮置灰，其他功能正常 |
| 麦克风 | 实时录音需要 | 多人／远场优先 USB 全向会议麦克风，笔记本内置麦在 3 人以上、2 米外基本不可用 |

### 4.2 安装

本插件以本地包形式安装到 desktop profile：

1. 把本包解压到 `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-meeting-live\`
   （包名 `dsh-meeting-live`）。
2. 编辑 `%USERPROFILE%\.dsh\profiles\desktop\package.json`：把 `dsh-meeting-live` 同时加入
   `dependencies` 与 `dsh.profile.bundles`。
3. 完全退出并重启 DSH Desktop。

> 改名只影响包名与插件标识：会议数据 `meeting-minutes.json`、媒体目录 `meeting-minutes-media`、
> 模型目录、接口前缀 `/dsh-meeting` 都保持不变，已有会议和设置不会丢。

### 4.3 第一次使用（三步）

- ① 打开左侧「会议纪要」→ 首次引导里点「去下载 / 配置模型」，把本地转写模型下载完（约 245 MB），或填好云端凭据。
- ② 点「实时录音/录屏」说几句话，确认能出字；录完点「AI 生成纪要」。
- ③ 生成的待办里勾选要落地的几条 → 「写入待办」→ 到 DSH 待办面板「工作」轨查看。

> 首次引导的第 3 步会检查 ffmpeg：没装时显示安装命令（`winget install Gyan.FFmpeg`，可一键复制），装完重启 DSH Desktop 生效；它只影响录屏和非 WAV 音视频转写，不影响录音、实时转写和纯文本纪要。

## 五、按场景怎么用

- **现场开会（Windows）**：点「实时录音/录屏」→ （可选）勾同步录屏并选屏幕 → 开始 → 收起主界面，用浮窗控制 → 会后「AI 生成纪要」→ 确认待办 → 导出 Word。
- **线上会外放／只有录音**：直接把会议录屏或录音文件丢进「录音转写」；或把文件放进「自动识别」的监控目录等它自己入库。
- **别人给了文字纪要**：「导入纪要」粘贴原文（或导入 txt/md/json）→「AI 生成纪要」。
- **腾讯会议**：设置 → 自动识别 → 打开「腾讯会议解析」并确认录制目录；之后的会议录完自动入库，打开就是待整理的会议。
- **查历史**：会议列表按标题／参会人搜索；详情页可展开原文、看分节纪要、导出；也可以在对话里问 AI（「上个月评审会的风险有哪些」）。
- **转写质量不满意**：先「整段重转写」补全文本 → 检查术语表 → 再「重新生成纪要」。

## 六、数据与隐私

- 会议数据全部在本机：`%USERPROFILE%\.dsh\storages\meeting-minutes.json`（结构化数据）与
  `%USERPROFILE%\.dsh\storages\meeting-minutes-media\<会议ID>\`（录屏、音频）。
- **默认本地转写，音频不出本机**；只有把转写引擎切成云端（讯飞／阿里云）时，音频分片才会发到对应厂商，按厂商价格计费。
- 会议总结走你配置的模型接口（DSH 默认模型或你自填的 OpenAI 兼容接口），转写文本会作为输入发给该模型。
- 云端凭据只保存在本机的会议数据文件里，不会上传到任何第三方；导出文件写到本机 `%USERPROFILE%\.dsh\meeting-minutes\exports\`。

**使用时的合规提醒（重要）**

- ① **录音／录屏前先告知参会人并取得同意**：录音、录屏可能涉及他人声音、头像、屏幕内容与会议信息；在单位内使用请同时遵守公司制度与当地法律。
- ② **声纹属于敏感个人信息**：本地说话人分离会用声纹特征区分 S1/S2（仅在本机计算、不保存声纹库）；如用于对外服务或客户会议，需要单独告知并取得同意。
- ③ **敏感／涉密会议不要用云端转写与外部模型**：切到云端转写会上传音频到厂商，生成纪要会把转写文本发给模型接口；涉密会议建议只用「本地模型 + 本机部署的模型」。
- ④ **会议数据为明文存放**：`meeting-minutes.json` 与录音文件在用户目录下明文保存，建议开启设备磁盘加密（BitLocker）并控制目录权限；云端凭据同样是明文，公用电脑上不建议填写。
- ⑤ **导出与分享由你控制**：导出的 Word/HTML/Markdown 含全文与参会人信息，转发前确认分发范围；删除会议时导出的旧文件不会被自动删除。

## 七、常见问题与能力边界

- **「写入待办」按钮是灰的**：装并启用 `dsh-memory-evolve`（与 `dtodo` 共用待办存储）。
- **转写一直不出字**：确认本地模型已下载完成；云端引擎要先把凭据填全（设置页会提示缺哪个字段）。
- **腾讯会议录完没自动识别**：确认「自动识别 → 腾讯会议解析」已打开、录制目录正确；只导入 14 天内新录制，旧文件用「录音转写」手动导入。
- **会议室开会没声音／识别不准**：会议室**需要接收音设备**——USB 全向会议麦克风放桌子中央，或从会议室调音台 / 会议主机 line-out 接到电脑的 line-in / USB 声卡；接好后在录音弹窗里选中这个设备并点「检测」，说话时电平条应过 1/3；外接麦建议在 Windows 声音设置关掉「音频增强／回声消除」，并开「整段重转写」+「转写纠错」。
- **没装 ffmpeg 会怎样**：录屏不可用（勾了也只会录音频）、腾讯会议录制（mp4/m4a）与监控目录里的非 WAV 音视频无法自动转写、在对话里让 AI 转写本地音视频也会失败；**实时录音/实时转写、页面「录音转写」导入、文本纪要、AI 纪要、待办、导出都不受影响**。安装：`winget install Gyan.FFmpeg`，装完重启 DSH Desktop；也可设 `FFMPEG_PATH` 指向已有的 ffmpeg.exe。
- **能力边界**（提前说明，避免误解）：
  - 实时转写是 5 秒分片拼接，断句和错字是常态，靠「整段重转写 + 纠错 + 术语表」改善；
  - 说话人分离解决「谁说的」，不解决「说得准」；方言、强噪声、多人抢话会明显掉准确率；
  - 自动识别只扫**本机**录制与监控目录，不连接腾讯会议云端纪要；
  - 桌面浮窗仅 Windows；其他平台用页面底部录音条；
  - 转写／总结的算力与费用由你选择的引擎和模型决定（本地模型免费、云端按厂商计费）。
- **问题反馈**：设置 → 问题反馈，扫码关注公众号「PM的AI手记」，把问题现象、复现步骤和截图发过来。
